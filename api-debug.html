Weekly Milestones

Pulls Bungie's public GetPublicMilestones endpoint and resolves every milestone hash it returns: name/description from DestinyMilestoneDefinition, the "about" blurb from GetPublicMilestoneContent, plus any activities/modifiers/quests/vendors attached to it this week, all resolved to real names. Nothing filtered or categorized. The point is to see the whole picture and figure out which hashes map to Vanguard, Crucible, vendors, etc. so we know what to automate FEATURED_THIS_WEEK and future section pages from.

Eververse (Tess Everis)

Prod already chased this down once, before this site had OAuth: Bungie's public/anonymous Vendors endpoint drops Tess entirely, confirmed via a 3-way diagnostic (full request, bare Vendors-only request, and her own definition fetched directly — she came back enabled:true, genuinely active, the endpoint just can't serve her). Matches Bungie's documented rule that a vendor gets dropped wholesale from the public endpoint if any part of it can't be computed identically for everyone. Prod ended up sourcing her from a third-party feed, eververse.report, instead — noted then as a stopgap "until this site has its own OAuth login."

That's now. This calls the authenticated, character-scoped Character/{id}/Vendors/?components=400,402 — untested territory, since it wasn't an option before. Confirmed working, and confirmed via live testing to be structured very differently than expected: Bright Dust offers aren't nested as sale items under a single Tess Everis vendor hash at all. Each Bright Dust item is its own separate one-item vendor stub — dozens of them, most with no display name of their own (shown as "Unknown (hash)" in the discovered-vendors list below), sitting alongside the handful of real, named NPC vendors. So this pulls sale items from every discovered vendor, not just whichever one happens to be named "Tess Everis"/"Eververse" — that name match now only stars the likely-Eververse entries in the list, it doesn't gate what gets collected. If nothing turns up this way, eververse.report is the proven fallback.

Items are grouped by whatever currency each one's own cost data resolves to (not hardcoded/assumed), but only the Bright Dust group actually renders below — Silver and no-cost items are still counted in the header for context, just not shown as cards. Each card also lists which vendor hash(es) it actually sold through, since most are unnamed stubs. The Bright Dust rotation refreshes at daily reset, so what's here is only good until tomorrow's reset.
